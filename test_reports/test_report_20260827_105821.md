## 5. 失敗ケースの詳細(エラー箇所・原因・改善案・影響範囲)

### ❌ TC-T15: TodoToolTest.RejectsFileWithUnrecognizedEscapeSequence

**エラー箇所**
`tests/TodoTool_test.cpp:163`

```
Expected equality of these values:
  tool.getTodos(0)
    Which is: 0x13747f6b140
  nullptr
    Which is: (nullptr)
```

**原因**
テストコード側のミスではなく、**対象コード(`ToolModels.h:60`)のバグ**。

`TodoTool::readJsonString`は、認識できないエスケープ文字(`\z`等)に遭遇した際、本来は`default: return false;`としてパース失敗を呼び出し元に伝える必要がある。しかしこのブランチでは`default: return true;`に変更されており、以下の壊れた挙動を引き起こす。

1. `"ab\zcd"` を読んでいる途中、`\z`(未対応エスケープ)に遭遇すると、`value`に`"ab"`だけが入った状態で誤って`true`(成功)を返す
2. しかし`index`は文字列の閉じ`"`まで進んでおらず、`\z`の直後の`'c'`の位置で止まっている
3. 呼び出し元(`loadFromJson`, `ToolModels.h:134`)は成功と判断し、**truncateされた`"ab"`をそのまま`todosByKey[0]`へ追加してしまう**
4. その後の解析で`'c'`が閉じ括弧`]`でもカンマでもないため整合性が崩れ、次の`readJsonString`呼び出しが(今度は正しく)失敗し`loadFromJson`全体を打ち切る

結果として、本来「不正なファイルとして読み込み全体を拒否し`todosByKey`は空のまま」となるべきところ、**「`"ab\zcd"`が壊れて`"ab"`という別のデータとして紛れ込む」**という、単なる読み込み失敗より悪い「サイレントなデータ破損」が起きている。

**改善案**
`ToolModels.h:60`
```cpp
                switch (escaped) {
                    case '"': value += '"'; break;
                    case '\\': value += '\\'; break;
                    case 'n': value += '\n'; break;
                    case 'r': value += '\r'; break;
                    case 't': value += '\t'; break;
-                    default: return true;
+                    default: return false;
                }
```
なぜこの修正が必要か: 同じファイル内の`MemoTool::readJsonString`(`ToolModels.h:285`)・`LogTool::readJsonString`(`ToolModels.h:509`)は共に`default: return false;`であり、`main`ブランチの`TodoTool::readJsonString`も同様。3クラスで動作が揃っていない状態そのものが設計上の矛盾であり、`true`を返す実装だけがデータ破損を引き起こす。

**影響範囲**
`readJsonString`は`private static`メソッドであり、`grep -rn "readJsonString(" --include="*.h" --include="*.cpp" .`で検索した結果、呼び出し元は同一クラス内の`loadFromJson`のみ(`ToolModels.h:107`のキー読込, `ToolModels.h:134`のtodo文字列読込)。

| 呼び出し元ファイル:行 | 現在のコード | 対応要否 | 呼び出し元側の修正案 |
|---|---|:---:|---|
| `ToolModels.h:107` (キー文字列読込) | `if (!readJsonString(json, index, keyText)) { return; }` | 不要 | 呼び出し側のロジックは正しい(`readJsonString`側の戻り値さえ修正すれば連動して正しく動作する) |
| `ToolModels.h:134` (todo文字列読込) | `if (!readJsonString(json, index, todo)) { return; }` | 不要 | 同上 |

検索範囲: リポジトリ全体(`.h`/`.cpp`)。上記2箇所以外に呼び出し元は見つからなかった。`readJsonString`自体の戻り値を修正するだけで、呼び出し元のコード変更は不要。

## 7. 総評

`false1`ブランチでは`TodoTool::readJsonString`(`ToolModels.h:60`)に、未対応エスケープ文字を検出した際の戻り値が`false`から`true`へ変更されるバグが混入しており、これによって不正なJSONを「パース失敗」ではなく「truncateされたデータの静かな取り込み」として処理してしまいます。既存テスト`TodoToolTest.RejectsFileWithUnrecognizedEscapeSequence`がこれを正しく検出しました。同じ関数を持つ`MemoTool`/`LogTool`側は変更されておらず、`LogToolTest`側の同種テストは全て成功しています。

修正自体は1行(`ToolModels.h:60`)で完結し、呼び出し元への影響もありません。修正を実際に適用する場合は、`main`への直接pushは行わず、featureブランチを切ってからの対応となります(ブランチ名はご指示ください)。適用してよろしければ教えてください。
